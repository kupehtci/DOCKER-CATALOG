# Dotnet

This folder contains a Dockerfile to containerize an .Net Application and run it with Docker Compose (Optionally).

The example application is `MyApi/`, an ASP.NET Core Web API (.NET 10) with a `ProductsController`, Swagger and a `/health` endpoint.

```
DotNet/
├── .dockerignore
├── Dockerfile
├── docker-compose.yaml
└── MyApi/
    ├── MyApi.slnx
    ├── MyApi.csproj
    ├── Program.cs
    └── controllers/
```

## Dockerfile

Multi-stage build: the SDK image compiles the application and only the published output is copied to the lighter ASP.NET runtime image.

**Build argument**:
* `DOTNET_VERSION` (default `10.0`): tag used for both `mcr.microsoft.com/dotnet/sdk` and `mcr.microsoft.com/dotnet/aspnet`. It must match the `TargetFramework` of the `.csproj`.

### Stage `build` (SDK image)

1. Copies only `MyApi.slnx` and `MyApi.csproj` and runs `dotnet restore`. This layer is cached, so the NuGet packages are only downloaded again when the project files change.
2. Copies the rest of the source code.
3. Runs `dotnet publish -c Release` into `/app/publish`. `/p:UseAppHost=false` skips the native executable, since the app is started with `dotnet MyApi.dll`.

### Stage `final` (ASP.NET runtime image)

1. Installs `curl`, used by the healthcheck (the base image does not include `curl` nor `wget`).
2. Creates `/app/logs` and gives ownership of `/app` to the non-root user.
3. Runs as the non-root user `app` (`$APP_UID` = `1654`, defined by the base image).
4. Copies the published application from the `build` stage.
5. Sets the environmental variables:
   * `ASPNETCORE_URLS=http://+:8080`: Kestrel listens on port `8080` over HTTP.
   * `DOTNET_EnableDiagnostics=0`: disables the debugger, profiler and EventPipe diagnostics (recommended for production and read-only filesystems).
6. Exposes port `8080` and starts the app with `dotnet MyApi.dll`.

### .dockerignore

Excludes `bin/`, `obj/` and IDE folders (`.idea`, `.vs`, `.vscode`) from the build context.

> **Important**: without it, `COPY MyApi/ ./` overwrites the `obj/project.assets.json` generated by the restore inside the image with the one from the host, which points to the local NuGet cache (e.g. `/Users/<user>/.nuget/packages`). The build then fails with `NETSDK1064: Package ... was not found`.

### Adapt to your application

* Replace `MyApi.slnx` / `MyApi.csproj` with your solution and project files. If your solution has several projects, copy every `.csproj` before the `dotnet restore`, keeping their folder structure.
* Change the DLL name in the `ENTRYPOINT`.
* Remove the `curl` installation if you do not use the healthcheck.

### Build and run without Compose

```bash
docker build -t myapi:local .
```

```bash
docker run -d --name myapi -p 8080:8080 myapi:local
```

## Docker Compose file

This configuration builds the image from the `Dockerfile` (tagged `myapi:local`) and deploys it in a container named `myapi`.

Exposed **ports**
* Port `8080` mapped to internal `8080` port for the HTTP API.

Configured **volumes**:
* myapi_logs → /app/logs for persistent application logs

Configured a **healthcheck** using `curl` against `/health` each 30s with 3 retries, a 5s timeout and a 15s start period.
Configured an **Auto-restart policy** unless is manually stopped.

### Configuration:

Build arguments:
* `DOTNET_VERSION`: .NET version of the SDK and runtime images

Configure the following environmental variables:
* `ASPNETCORE_ENVIRONMENT`: Runtime environment (`Production`, `Development`...). Swagger is only enabled in `Development`.
* `ASPNETCORE_URLS`: Address and port where Kestrel listens.
* `Logging__LogLevel__Default`: Default log level. Any value of `appsettings.json` can be overridden this way, replacing `:` with `__`.

## How to start

Build and launch the service.
```bash
docker compose up -d --build
```

Check the status (it should be `healthy`):
```bash
docker compose ps
```

Test the endpoints:
```bash
curl http://localhost:8080/health
```

```bash
curl http://localhost:8080/api/products
```

To enable Swagger, set `ASPNETCORE_ENVIRONMENT: Development` and open http://localhost:8080/swagger

Show the logs:
```bash
docker compose logs -f myapi
```

Stop and remove the container:
```bash
docker compose down
```
